## Findings

### 1. Stable main already contains strong reusable primitives, but they are split across task-specific systems

**Release/source binding.** `src/sparkbrain/release.py` provides canonical file inventory, file size/SHA-256 validation, artifact classes, archive/repository completeness checks, release-metadata-to-manifest binding, source-revision validation, and revision consistency checks. This is a strong generic provenance/file-integrity substrate, but it is a package/release validator rather than a two-run scientific-equivalence certificate.

**Exact identity creation.** `create-authoritative-tag.yml` validates an exact 40-character target commit, verifies the commit exists, refuses an existing authoritative tag, creates an annotated tag without force, and verifies the remote peeled commit. It records `protocol_identity` and `package_identity` as metadata strings, but this workflow does not itself resolve those strings and machine-check them against target content before tagging. That is acceptable for its current identity-creation role, but means it is not a generic contract-equivalence verifier.

**Independent reproduction / exact-byte comparison.** `scripts/run_c17_organs.py` is the closest reusable precedent. It verifies canonical protocol bytes, source pins/scope, protected hashes, fixture hashes and resource conditions; then launches two distinct workers with distinct process contracts and challenge nonces. Each worker attests process id, PID, `PYTHONHASHSEED`, source commit, protocol SHA-256, output directory, inventory and per-file/combined digests. The parent re-derives hashes, verifies attestations, requires distinct producers, and only then authorizes exact pre-final bundle equality. The comparison manifest binds the comparison contract, inventory and run records. Tests explicitly reject forged digests, wrong PID/challenge/return code and attempts to fabricate reproduction authority.

**Matched-resource structural validation.** `src/sparkbrain/v03_organs/contracts.py::validate_resource_conditions` fail-closes unless there are exactly five ordered resource cells and each secondary cell changes exactly one numeric resource factor from the primary. `tests/test_c17_organs.py` verifies that a two-factor drift is rejected and that resource interventions share pre-resource bank/checkpoint identities while producing distinct evaluation behavior where intended. This is useful structure, but is C17-specific rather than a generic pairwise privilege/resource-envelope schema.

**Experiment-local equivalence.** `scripts/run_spiking_comparison.py` freezes versions, device, LIF configuration and behavior tolerances, then reports exact and bounded behavioral checks. It is another useful local pattern, but it does not provide the source/protocol/package/producer/resource-envelope cross-binding that a reusable generic verifier would need.

### 2. The missing layer is a generic machine-verifiable certificate, not a lack of validation code

The stable-main `schemas/` directory contains domain/run/config/result schemas, but the bounded inspection found no generic equivalence-certificate schema. Repository search found no `certificate` implementation and `equivalence` hits were experiment-specific documentation/comparison code rather than a reusable cross-experiment verifier. Therefore the current gap is best characterized as **fragmented verification primitives with no single generic fail-closed certificate contract**.

The important consequence is architectural: future work should not reimplement ad-hoc equality checks inside each scientific runner. Existing primitives can be extracted into a development-only verifier that certifies only that a prospective comparison contract was satisfied. It must not decide whether a candidate is valid, promoted, READY, PRE_FORMAL, or FORMAL.

## Minimal prospective generic contract

A reusable `equivalence-certificate-v0.1` should be outcome-independent and require, at minimum:

1. **Contract identity** — schema version, comparison contract id/version, comparison mode (`exact` by default), and a digest of the complete comparison policy.
2. **Bound identities for both sides** — exact source commit, protocol digest, package/release-manifest digest, fixture/input-manifest digest, evaluator/tool digest where applicable, and run identity.
3. **Privilege envelope** — explicit readable input/split namespaces, evaluator/target accessibility, network policy, environment-variable/secret capability class, and any permitted asymmetry. Missing privilege declarations fail closed.
4. **Resource envelope** — CPU/GPU/device class, thread/process limits, memory/runtime limits where contract-relevant, seed/hashseed/determinism configuration, and semantic resource parameters. Fields designated `must_match` require exact equality; intentionally varied fields must be predeclared.
5. **Independent-producer attestation** when required — producer/process identity, fresh challenge nonce, source/protocol digests, output inventory and per-output digests. The verifier re-hashes artifacts rather than trusting attested hashes.
6. **Ordered semantic streams/checkpoints** — named ordered sequences with count, canonical encoding and digest for every prospectively required trajectory/checkpoint class. Equality is established from independently generated bytes/digests, not by construction in one shared producer.
7. **Decision surface** — verifier output limited to `VALID_EQUIVALENT`, `VALID_NOT_EQUIVALENT`, or `INVALID_CONTRACT`, plus structured mismatch reasons. It must contain no scientific interpretation or Funnel authority.

For exact mode, tolerances should be forbidden. If a future non-exact mode is needed, every tolerance and aggregation rule must be part of the prospectively hashed comparison policy; runtime code cannot relax it.

## Minimal reusable implementation shape

A later Control-approved isolated tooling prototype could consist of:

- `schemas/equivalence-certificate-v0.1.schema.json`
- a pure verifier module such as `src/sparkbrain/verification/equivalence.py`
- an optional CLI wrapper that only reads bound manifests/artifacts and emits a certificate
- unit tests porting existing C17 failure modes: missing/extra keys, duplicate stream ids, reordered checkpoints, forged artifact hash, source/protocol/package mismatch, privilege mismatch, undeclared resource drift, same-producer use when independence is required, missing challenge/attestation, and tolerance use in exact mode

The implementation should reuse canonical JSON/SHA-256 and strict-schema idioms already present on stable main rather than copy a scientific runner.
