## SUB Discovery review

Classification: **`PROMOTE_TO_ARCHITECTURE_STUDY`**.

The SUB result is strictly NON_EVIDENTIARY. The current implementation explains the mechanism exactly: `ingest_pulses()` sorts the external rows, calls `expectations.observe()` on all rows, and only then calls `expectations.poll()` through the batch end. Because `observe()` updates `last_time`, interval state, and clears the emitted deadline, a later observation in the same call can suppress an omission that would have been generated if event-time had been advanced between observations.

This is not evidence of a new cognitive mechanism. It is an Architecture/API semantics question with engineering/reproducibility value because repository-supported paths use both per-pulse ingestion (`evaluate_repetition_and_omission`) and multi-time batched ingestion (`evaluate_temporal_order`, `evaluate_noisy_motif`, examples/docs, and the v0.5 wrapper). A real Architecture study can therefore ask whether partition choice changes omission schedules and whether those schedule differences propagate into downstream field/cascade/action behavior on fixed repository reference timelines.

SUB must not continue this candidate after promotion. Its synthetic timeline and observed result may motivate the fresh Architecture object, but must not be reused as a tuned success surface or future formal evidence.
