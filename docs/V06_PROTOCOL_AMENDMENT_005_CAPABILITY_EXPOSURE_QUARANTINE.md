# SparkBrain v0.6 Protocol Amendment 005
## Pre-Freeze Capability Exposure Quarantine and Fresh Confirmatory Generation

**Amendment date:** 2026-08-30  
**Status:** normative  
**Supersedes:** any statement that the 100-series held-out-labelled adapter run was outcome-blind  
**Preserves:** development qualification, Relation Re-entry, Persistence Locus, and schema-only preflight work

## 1. Finding

Repository review found that the former held-out adapter preflight imported and called real capability entrypoints. It instantiated real `passed` values and dynamic resource measurements for a subset of held-out-labelled worlds before code, manifest, thresholds, schemas, and execution command were frozen.

No complete 3,600-record matrix was formally scored. Nevertheless, capability behaviour was exposed. Lack of aggregation does not make an actual capability execution outcome-blind.

## 2. Quarantine decision

All capability observations made on the former 100-series held-out-labelled set are reclassified as contaminated development material.

```text
quarantined seeds: 100 through 109
confirmatory evidence status: ineligible
threshold/world tuning use: prohibited
historical deletion: prohibited
```

The exact pre-correction repository state is preserved at:

```text
archive/v06-pre-freeze-capability-exposure-20260830
```

The active `v06` branch removes the unsealed capability dispatcher, capability adapters, and tests that invoked them. This prevents ordinary CI from generating further held-out outcomes.

## 3. Fresh candidate generation

A new disjoint candidate generation replaces the contaminated set:


The new RNG salt, unit/port permutations, timing values, thresholds, paths, and contingency details differ from the quarantined generation. The candidate specifications may be built, hashed, inspected, and passed through schema-only adapter declarations. They must not be passed to a capability runtime before freeze.

## 4. Allowed work before freeze

Repeated preflight may verify:

- all 50 world specifications reconstruct exactly from fixed seeds;
- every one of the eight adapter declarations receives the identical canonical world mapping;
- topology, active/distractor support, threshold, magnitude, lag profiles, episode spacing, ports, branch alternatives, exposure counts, and contingency cycles reach adapter configuration;
- branch competition remains a genuine three-path structure;
- result and resource schemas are complete for 400 execution cells and 3,600 domain cells;
- schema rows remain `unscored` and contain no capability result;
- dynamic resource measurements remain absent;
- G3/G4/G5 do not import or inspect Primary runtime state;
- comparator privileges and Field-threshold bypasses are explicit;
- taxonomy, self-confirmation, observation provenance, and privilege guards fail closed;
- confirmatory manifest readiness remains false;
- no capability entrypoint exists on the active pre-freeze protocol branch.

Development and qualification capability tests may continue on development-only worlds.

## 5. Prohibited work before freeze

Before a valid execution seal exists, no process may:

- run Primary, controls, G3, G4, or G5 on candidate-002 events;
- instantiate a candidate-002 `passed` value;
- populate measured candidate-002 resource values;
- compute family, seed, condition, or aggregate success;
- inspect a partial candidate capability trace;
- tune code, thresholds, gains, lag tolerance, branch handling, exclusions, or world definitions from candidate capability behaviour;
- mark a held-out capability adapter ready because a schema-only declaration passes.

## 6. Execution seal

The final dispatcher must call `require_execution_seal(...)` before reading any candidate world.

A valid seal binds all of the following:

- full lowercase 40-character Git SHA;
- exact confirmatory manifest hash;
- world-generation ID;
- 50-world grid hash;
- threshold hash;
- exclusion hash;
- result-schema hash;
- resource-schema hash;
- adapter-inventory hash;
- execution-command hash;
- artifact-path hash;
- explicit review approval.

Any mismatch blocks execution.
