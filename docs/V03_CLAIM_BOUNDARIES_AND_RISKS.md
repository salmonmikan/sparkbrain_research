# SparkBrain v0.3 — Claim boundaries and risks

## Permitted descriptions

- local dynamic cognition research system
- adaptive sensory-selection prototype
- evidence-based Coalition gate
- entity-scoped persistent belief state
- label-free concept candidate
- functional-organ candidate
- brain-inspired computational hypothesis

## Prohibited interpretations

The following are not supported by the v0.3 release evidence: semantic understanding,
autonomous concept formation, functional concept formation, an organ having formed, human-like
perception, consciousness, subjective awareness, AGI, general energy efficiency, or truly
asynchronous hardware. A passing engineering gate does not waive the specific prerequisite for
any of these claims.

## Active risk controls

| Risk | Release control |
| --- | --- |
| Oracle leakage | Keep Oracle conditions separate and exclude them from autonomous aggregates. |
| Biological analogy overreach | Label biological vocabulary as inspired/reference/candidate and retain its software contract. |
| Coalition decoration | Retain fixed-logit intervention and no-Coalition ablation evidence. |
| Concept or organ overclaim | Require preregistered causal and matched-control gates; retain null/negative results. |
| Test tuning | Keep official test data outside selection/calibration and retain protocol pins. |
| Legacy regression | Preserve v0.2.1 schema, artifacts, protected hashes, and compatibility tests. |
| External evaluation gap | Mark C19 as blocked until a pinned, independently auditable result is integrated. |

## Claim-register rule

Every release claim must identify a claim ID, scope, condition, metric/artifact, status,
strength grade, known counterevidence, and review date. A stronger grade requires new v0.3
evidence linked to a preregistered gate. Absence of a match, a blocked external run, or a
negative result is never converted into a novelty or performance claim.
