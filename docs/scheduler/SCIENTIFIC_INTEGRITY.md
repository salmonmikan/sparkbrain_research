# SparkBrain Scientific Integrity Floor

These constraints are always active for scientific work and are not weakened by P0 recovery, scheduler policy, review policy, SYSTEM_BUILD, Forge, or user authorization for ordinary GitHub operations.

## One-way scientific rules

- Never rerun, retune, rescore, redispatch, or otherwise repeat a consumed FORMAL identity.
- Never retarget, rewrite, delete, force-move, or silently replace authoritative immutable/freeze/sealed/formal/evidence refs.
- Preserve prospective/frozen protocols, exact binding, STARTED/no-clobber, raw-before-score, preserve-before-read/score, matched privilege/resources and target/held-out isolation.
- No evaluator or held-out leakage.
- No silent post-FORMAL repair or outcome-responsive rescue.
- No historical PASS/FAIL rewriting.
- A terminal scientific object remains immutable history and never returns to ACTIVE.
- Same-object post-outcome SYSTEM -> MECHANISM uplift is forbidden.
- A fresh successor requires a new prospective scientific object and independent trigger/contract.

## Development phases

- `OPEN_DEVELOPMENT`: prospective iteration is allowed.
- `RESULT_EXPOSED_DEVELOPMENT`: science-invariant repair may remain on the same object; science-affecting redesign requires an explicit revision or fresh successor.
- `CONSUMED_ONE_WAY`: strict irreversible identity.

PRE_FORMAL is development, not one-way FORMAL evidence.

## Claim typing

Keep `SYSTEM` and `MECHANISM` claim ceilings distinct. Keep:
- component function,
- integrated system construction,
- causal contribution,
- scientific novelty

as separate conclusions.

Known/reduced mechanisms may be reused in SYSTEM_BUILD with explicit provenance and zero inherited scientific credit.

## BUILD / Forge boundary

SYSTEM_BUILD, Theory synthesis, Revisit proposals and Fast Forge are not confirmatory scientific evidence. An interesting build/Forge observation can motivate a fresh scientific object but does not count as confirmation for it.

## Truthfulness

Negative, inconclusive, reduced and invalid evidence must remain visible. Do not strengthen claims because implementation is polished, CI is green, a review passed, or a system-level demo looks compelling.
