# SparkBrainの基礎理論 — 初めて読む人のためのやさしい解説

## 0. この文書の目的

この文書は、ニューラルネットワークや脳科学の専門知識がない人でも、SparkBrainが何を作ろうとしているのかを理解できるように書いている。

数式を完全に理解しなくても読める。数式は「実装と議論を曖昧にしないための短い設計図」として後半で説明する。

SparkBrainには形式的な仕様書 `THEORY_SPEC_v0.2.1.md` がある。この文書はそれを置き換えるものではなく、形式仕様へ入る前の橋渡しである。

---

## 1. 何を作ろうとしているのか

SparkBrainの最終成果物は、ローカルPC上で起動できる人工脳実験環境である。

利用者は、人工的な外界から刺激を与え、内部で多数のSparkがどのように活動し、どの仮説が強まり、どの仮説が弱まり、いつ判断が成立したのかを観察する。

理想的な操作イメージは次のとおり。

```text
[刺激を入れる]
       ↓
Sparkが局所的に活動する
       ↓
仮説同士が競争する
       ↓
証拠の組がCoalitionになる
       ↓
十分な条件を満たすとIgnitionする
       ↓
Workspaceへ共有される
       ↓
記憶・行動・次の思考が変化する
```

人工脳と呼んではいるが、人間の脳を解剖学的に再現することが直近の目標ではない。まずは、脳に見られる次のような**計算上の特徴**を模倣する。

- 多数の小さな活動が並列に存在する
- すべてが最終判断になるわけではない
- 活動は時間とともに強くなったり弱くなったりする
- 候補同士が競争する
- 複数の証拠が揃うことで判断が成立する
- 一度負けた仮説も完全には消えず、後から復活できる
- 全部を毎回計算せず、関係する場所だけを更新する

---

## 2. 最も大切な発想: 知能を「状態の時間変化」として扱う

一般的なプログラムは、入力を与えると出力を返す関数として説明できる。

```text
出力 = 関数(入力)
```

LLMも実際には非常に複雑だが、大まかには文脈を入力し、次のトークンの確率を出す巨大な関数として扱える。

SparkBrainでは、中心を次のように置く。

```text
次の脳状態 = 状態遷移(現在の脳状態, 新しいイベント)
```

ここで重要なのは、同じイベントが来ても、現在の内部状態が違えば結果が変わり得ること。

たとえば「ニャーという音」が来たとする。

- 直前に「毛がある」を見ていれば、猫仮説が強くなる
- 直前に「スピーカーから音が出た」を見ていれば、録音仮説が強くなる
- 猫仮説が疲労状態なら、同じ刺激でも発火しないかもしれない

知能を、静的な入力変換ではなく、**履歴を持つ動的な系**として扱う。

## 3. Sparkとは何か

Sparkは、SparkBrainにおける最小の機能的な活動単位である。

ただし、Sparkを生物のニューロン1個と同一視してはいけない。Sparkは用途によって、次のいずれかに近い役割を持つ。

- 「毛が見えた」という特徴
- 「猫かもしれない」という仮説
- 「以前ここに猫がいた」という記憶
- 「近づきたい」という目標
- 「手を伸ばす」という行動候補

Sparkは、少なくとも次のような状態を持つ。

```text
名前・役割
活動値 activation
発火閾値 threshold
時間による減衰
一時的な発火禁止時間 refractory
残りやすさ residual
支持証拠
反証
接続先
```

やさしく言えば、Sparkは「脳内でいま少しだけ起きている考え・特徴・記憶の火種」である。

## 4. ActivationとThreshold

### Activation — 活動値

Sparkが現在どれだけ強く活動しているかを表す数値。

```text
0.0  ほぼ活動していない
0.4  少し気になっている
0.9  かなり強い
1.2  閾値を超えて発火
```

数値自体に普遍的な意味はなく、モデル内の比較に使う。

### Threshold — 閾値

Sparkが発火するために必要な活動値。

```text
activation = 0.8
threshold  = 1.0
→ まだ発火しない

activation = 1.1
threshold  = 1.0
→ 発火する
```

発火は「このSparkが周囲へ影響を伝えるイベントが起きた」という意味である。発火したからといって、それだけで最終判断になるわけではない。

---

## 5. Event — 何かが起こったという通知

SparkBrainは、全Sparkを同じ周期で更新し続けるのではなく、基本的にEventを処理する。

Eventの例:

- 外界から「毛が見えた」が来る
- Spark Aが発火し、Spark Bを刺激する
- 仮説Sparkが競合仮説を抑制する
- Workspaceが記憶領域へ内容を共有する
- 行動結果に対して報酬が来る

Eventには、いつ、どこから、どこへ、どれくらいの強さで、何の証拠として届いたかを持たせる。

この方式をevent-driven、つまりイベント駆動と呼ぶ。

---

## 6. ExcitationとInhibition

### Excitation — 興奮

相手の活動値を上げる作用。

```text
「ニャー」Spark
      ↓ 興奮
「猫」仮説Spark
```

### Inhibition — 抑制

相手の活動値を下げる作用。

```text
「猫」仮説が強くなる
      ↓ 抑制
「犬」仮説が弱くなる
```

抑制は「犬ではないという外部証拠」と同じではない。内部競争として弱められたことと、外界から反証を受けたことは区別する。

この区別がないと、システム自身が作った抑制を、独立した証拠だと誤認してしまう。

---

## 7. Decay、Residual、Refractory、Homeostasis

### Decay — 減衰

刺激がなければ、活動値は時間とともに弱まる。

人間でも、数秒前に気になっていたことが、新しい刺激がなければ薄れていく。それに似た働き。

### Residual — 残留

発火した後や競争に負けた後に、どれだけ活動を残すか。

SparkBrainでは、負けた仮説を必ずゼロにしない。

```text
猫  1.20 → 勝者
玩具 0.55 → 敗者だが残る
```

その後「プラスチックの継ぎ目」が来れば、玩具仮説が復活できる。

### Refractory — 不応期

発火直後に、同じSparkがすぐ連続発火しないようにする短い休止期間。

これがないと、一つのSparkが無限に自己増幅することがある。

### Homeostasis — 恒常性調整

活動しすぎるSparkは一時的に発火しにくくし、活動しなさすぎるSparkは必要に応じて発火しやすくする考え方。

一部のSparkだけが永久に勝ち続けることを防ぐ。

---

## 8. Evidence、Support、Contradiction

### Evidence — 証拠

外界から得られた観測記録。

例:

- evidence ID: camera-001
- source: camera
- label: fur
- time: 10.2
- strength: 0.6

同じ観測が複数のSparkを伝播しても、独立した証拠が増えたとは数えない。そのためにevidence IDを保持する。

### Support — 支持

ある証拠が仮説を強める関係。

```text
毛がある → 猫を支持
ニャー    → 猫を強く支持
```

### Contradiction — 反証・矛盾証拠

ある証拠が仮説を弱める関係。

```text
プラスチックの継ぎ目 → 生きた猫仮説を反証
```

SupportやContradictionは、真実そのものではない。センサーが間違う可能性も、ルールが不完全な可能性もある。

---

## 9. 複数仮説を同時に持つ

SparkBrainでは、相互排他的な仮説も同時に非ゼロで存在できる。

```text
猫   0.72
犬   0.26
玩具 0.48
```

これは「三つを同時に正しいと信じている」という意味ではない。未確定の候補を捨てずに持っているという意味。

この状態をpersistent competing beliefs、持続する競合仮説と呼ぶ。

---

## 10. Winner-Take-Most

Hard Winner-Take-Allでは、最も強い候補だけを残し、他を消す。

```text
猫   1
犬   0
玩具 0
```

SparkBrainの標準はWinner-Take-Mostである。

```text
猫   1.00
犬   0.08
玩具 0.31
```

勝者が多くを取るが、敗者を完全消去しない。これにより、後から新証拠が来たときに意見を変えられる。

---

## 11. Coalition — 証拠とSparkの一時的な連合

単一のSparkが強いだけでは、判断として不十分な場合がある。

たとえば、音声センサーが誤作動して「ニャー」と一度だけ出したとしても、猫と確定するのは危険。

そこで、同じ仮説を支える複数のSparkと証拠を、一時的なCoalitionとして扱う。

```text
毛がある ─┐
ニャー   ─┼→ 「猫」Coalition
温かい   ─┘
```

Coalitionは永久的な器官ではない。その時点の仮説を支える一時的な組み合わせである。

評価には、次のような要素を使う。

- 中心仮説の活動値
- 支持証拠の強さ
- 異なる情報源の数
- 一定時間安定しているか
- 反証がどれだけあるか

---

## 12. Ignition — 判断を全体へ共有する門

Coalitionの点数が高くても、ただ一瞬だけ高かった場合や、二番手との差が小さい場合は、まだ判断を確定しない。

Ignitionには、たとえば次の条件を使う。

```text
Coalition scoreが閾値以上
かつ
二番手との差が十分
かつ
異なる証拠源が一定数以上
かつ
一定時間安定
```

条件を満たすとIgnitionが起き、CoalitionがGlobal Workspaceへ昇格する。

Ignitionは意識の証明ではない。あくまで、局所的な候補をシステム全体へ共有するためのゲートイベントである。

---

## 13. No-Ignition — 分からないまま待つ

どのCoalitionも条件を満たさない場合、SparkBrainは判断を新規確定しない。

```text
猫   0.43
犬   0.41
玩具 0.40
→ NO IGNITION
```

これはエラーではない。

「まだ十分な根拠がない」という内部状態を、文章で無理に「分かりません」と出力するのではなく、計算機構そのものが保持する。

---

## 14. Global Workspace — 限られた共有掲示板

Global Workspaceは、システム内の全情報を入れる巨大倉庫ではない。容量が限られた共有領域である。

CoalitionがIgnitionすると、その内容が次のような機能へbroadcastされる。

- 記憶
- 行動選択
- 計画
- 評価
- 言語化

たとえるなら、多数の部署が個別に仕事をしている会社で、重要な案件だけが全社掲示板へ載るようなもの。

Workspace自体が全部を決める小人や中央司令官ではない。

---

## 15. Belief RevisionとRecovery

### Belief

SparkBrainでのbeliefは、主観的な信念ではなく、課題について持続している仮説状態を指す。

### Necessary Revision — 必要な更新

世界が本当に変わった、または決定的な新証拠が来たため、現在の仮説を変えること。

### Unnecessary Revision — 不要な更新

世界が変わっていないのに、ノイズだけで仮説を変えてしまうこと。

### Recovery — 復帰

一度負けた仮説が、新証拠によって再びIgnitionすること。

良いシステムは、何でもすぐ変えるのでも、絶対に変えないのでもない。

```text
ノイズには安定
決定的反証には柔軟
```

この両立をstability–plasticityと呼ぶ。

---

## 16. Memory — 記憶の段階

### Residual working state

Sparkの活動や証拠が短時間残る。最も短い記憶。

### Workspace memory

Ignitionした内容が、容量制限つきでしばらく共有される。

### Episodic memory

「ある状況で、何が起き、何を判断し、どうなったか」という出来事単位の記憶。将来実装。

### Semantic memory

繰り返し成立した関係を、一般知識として再利用できる構造へまとめる。将来実装。

---

## 17. Organ — Spark群による機能領域

Spark一個を器官とは呼ばない。

多数のSparkが、共通の機能、接続、競争範囲、時間特性を持つとき、その集合をOrganと呼ぶ。

例:

- 感覚Organ
- 仮説Organ
- 記憶Organ
- 目標Organ
- 行動Organ

v0.xでは多くのOrganを設計者が定義する。

最終的には、学習と構造変化の結果として、繰り返し一緒に働くSpark群が形成され、後から「この群は記憶機能を担っている」と同定できる状態を目指す。これをemergent organ、創発的器官と呼ぶ。

ただし、見た目のクラスタができただけでは器官が生まれたとは言わない。その群を抑制したとき特定機能だけが落ちる、といった因果介入が必要になる。

---

## 18. LearningとPlasticity

固定ルールだけで動くSparkBrainはシミュレーターではあるが、十分な学習系ではない。

学習では、経験に応じて次を変える。

- 接続の強さ
- 発火閾値
- どのイベントをどのSparkへ送るか
- Sparkの作成、分割、統合、削除
- Organの構成

### Eligibility trace

ある接続が直前の判断にどれだけ関与したかを、短時間残す印。

### Reward-modulated learning

後から報酬または失敗が来たとき、eligibilityの高い接続を中心に強めたり弱めたりする。

```text
ある接続が判断に関与した
        ↓
少し後に成功報酬が来た
        ↓
その接続を強める
```

v0.2.1の実装は最小限であり、end-to-end学習が完成したわけではない。

---

## 19. Routing、Top-k、Sparse Execution

### Routing

入力イベントを、関係するSparkへ振り分けること。

### Top-k routing

候補の中から関連度上位k個だけを選ぶこと。

```text
全Spark 8,192個
        ↓
入力に関係する上位16個
        ↓
その近傍を含む64個だけ更新
```

### Sparse execution

全Sparkを毎回計算せず、活動している一部だけを処理すること。

これはアルゴリズム上の活動量を減らす可能性があるが、直ちに消費電力が低いことを意味しない。PythonやGPUでは、疎な処理の管理コストが大きい場合もある。

---

## 20. Trace、Checkpoint、Replay

### Trace

時間ごとの活動値、発火、Coalition、Ignition、Workspace、因果経路を記録したもの。

### Checkpoint

途中時点の人工脳状態を保存したもの。再読込して同じ場所から続ける。

### Replay

保存されたtraceを使って、エンジンの計算をやり直さずに内部状態の推移を再生すること。

Visualizerは、traceに存在しない状態を勝手に補完してはいけない。

---

## 21. World、Benchmark、Baseline、Ablation

### World

人工脳が置かれる実験環境。外界状態、センサー、ノイズ、行動、報酬を持つ。

### Benchmark

同じ条件で複数方式を測る実験セット。

### Baseline

比較対象となる既存または単純な方式。

例:

- 単純加算器
- Hard WTA
- GRU
- Transformer
- Bayesian / HMM

### Ablation

SparkBrainから一つの機能を外し、その機能が本当に必要だったか調べる実験。

```text
完全版
residualなし
coalitionなし
inhibitionなし
```

完全版が良かっただけでは、何が効いたのか分からない。Ablationによって因果を切り分ける。

## 22. Accuracyだけでは足りない理由

SparkBrainでは、最終正答率だけでなく次を測る。

- False ignition: 根拠不足なのに判断した率
- Revision precision: 意見を変えたとき、それが必要だった割合
- Revision recall: 変えるべきときに変えられた割合
- Switch latency: 世界が変わってから追従するまでの遅れ
- Unnecessary revision: ノイズで意見を変えた率
- Recovery rate: 一度負けた正しい仮説が復活した率
- Calibration: 70%自信がある判断が実際にも約70%正しいか
- Active Spark ratio: 全Sparkの何割を処理したか

最速で意見を変えるだけなら、ノイズにも振り回される。絶対に意見を変えなければ、環境変化に対応できない。複数指標のバランスを見る。

---

## 23. Pareto Frontier — 一つの点数に潰さない

二つの目標が衝突するとき、一方だけを最大化した単一順位では不十分。

例:

- 安定性を上げると追従が遅くなる
- 追従を速くすると誤反転が増える

どちらか一方を改善しようとすると他方が悪化する優良な境界をPareto frontierと呼ぶ。

SparkBrainが有効なら、既存方式よりも「安定しているのに必要なときは速く変わる」側へ境界を押し広げる可能性がある。

---

## 24. Falsifiability — 間違っていると判定できる理論にする

理論は、どんな結果でも「成功」と言える形にしてはいけない。

SparkBrainでは、たとえば次が観測されたら中心仮説が弱まる。

- residualを外しても復帰性能が変わらない
- coalitionを外しても誤Ignitionが増えない
- 単純な加算器が全条件で同等以上
- sparse routingでは成立せず、全ノード計算が必須
- traceで説明される原因と実際の出力決定が一致しない

失敗結果も成果として保存する。

## 25. 数式をやさしく読む

### 中心式

\[
B_{t+1}=F(B_t,E_t;\phi)
\]

読み方:

- \(B_t\): 今の人工脳全体の状態
- \(E_t\): 今回届いたイベント
- \(\phi\): 接続、閾値、ルール等の設定
- \(F\): 状態を一段進める処理
- \(B_{t+1}\): 更新後の人工脳状態

言葉にすると:

> 今の内部状態と新しい出来事を使って、次の内部状態を作る。

### 減衰

\[
a_i(t)=a_i(t_0)e^{-(t-t_0)/\tau_i}
\]

言葉にすると:

> 最後に触れた時の活動値を、経過時間に応じて少しずつ弱くする。

\(\tau\) が大きいSparkほど長く残る。

### Coalition score

\[
Q=A+\alpha P+\beta D+\chi K-\delta N
\]

言葉にすると:

> 仮説自身の強さ、支持証拠、証拠源の多様性、時間的安定性を足し、反証を引く。

各係数は、それぞれをどれだけ重視するかを表す。

### Ignition

\[
Q(C^*)\geq\Theta_I
\]

だけでなく、二番手との差、証拠源数、安定時間も確認する。

言葉にすると:

> 一瞬強いだけではだめで、十分強く、競合より優位で、複数の根拠があり、少しの間安定した候補だけを全体へ共有する。

## 26. 猫と玩具の例を最初から最後まで

### t1: 毛がある

```text
猫   0.48
犬   0.36
玩具 0.00
```

猫も犬もあり得る。Ignitionしない。

### t2: ニャーと鳴く

```text
猫   1.20
犬   0.10
玩具 0.00
```

「毛」と「ニャー」が異なる証拠として猫Coalitionを作る。条件を満たせば猫がIgnitionする。

### t3: 動かない

```text
猫   0.87
玩具 0.55
```

猫はまだ勝者だが、玩具仮説が強まる。猫を即座に消さない。

### t4: プラスチックの継ぎ目

```text
猫   0.42
玩具 1.25
```

玩具CoalitionがIgnitionし、belief revisionが起きる。

### t5: 身体が温かい

```text
猫   0.71
玩具 0.76
```

拮抗し、No-Ignitionになる可能性がある。

### t6: ゴロゴロ鳴く

```text
猫   1.40
玩具 0.53
```

残っていた猫仮説が復帰し、再びIgnitionする。

この例が示す中心動作は、判断、反証、保留、復帰である。

## 27. 今のLLMとの主な違い

これは完全な二分ではない。LLM内部にも注意、競争、疎なExpert、暗黙の仮説表現はあり得る。

それでもSparkBrainが明示的に設計する差は次のとおり。

| 観点 | 一般的なLLM | SparkBrainの目標 |
|---|---|---|
| 基本単位 | tokenの分散表現 | 名前と状態を持つSpark |
| 仮説 | 内部表現に暗黙的 | first-class stateとして複数保持 |
| 時間 | 主にtoken系列 | 系自体が状態を持ち続ける |
| 出力 | 生成時は何かを選ぶ | No-Ignitionを正規状態にできる |
| 競争 | 内部に分散・暗黙 | 抑制関係として監査可能 |
| 証拠 | attention等に暗黙 | evidence IDとsourceを記録 |
| 失敗候補 | 次の計算で再構成され得る | residual stateとして明示保持 |
| 計算 | denseまたはMoE | event-routed active subsetを目標 |
| 観察 |解釈が難しい | traceを理論状態として要求 |

SparkBrainがLLMより優れていると現時点で主張するものではない。異なる設計原理を、比較可能な形にすることが目的。

## 28. ローカル完結という条件

v0.2.1から、コア成果物は一台の一般的なPCで完結することを正式条件とする。

必須:

- CPUで参照エンジンが動く
- 外部APIなしで実験できる
- trace、checkpoint、reportをローカル保存する
- UIは静的HTMLまたはlocalhostで動く
- セットアップ後はオフライン実行できる

任意:

- ローカルGPU
- PyTorch
- ローカルSNNライブラリ
- Docker

別枠:

- Loihi等の専用ハードウェア
- FPGA / ASIC
- クラウド学習
- 実電力測定

詳細は `LOCAL_EXECUTION_POLICY.md` を参照する。
