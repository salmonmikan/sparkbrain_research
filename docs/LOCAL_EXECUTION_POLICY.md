# Local-Only Execution Policy — v0.2.1

## 1. この文書の役割

SparkBrain の正式な完成条件を、**一般的な一台のローカルコンピューター上で完結すること**に固定する。

ここでいう「ローカル完結」は、単にPythonファイルが手元にあるという意味ではない。人工脳エンジン、実験環境、可視化、学習、保存、再生、比較、レポート生成までを、外部サービスへ処理やデータを送らずに実行できることを意味する。

専用ニューロモーフィックハードウェア、FPGA、ASIC、クラウドGPU、分散クラスタは、コア成果物の完成条件から外す。それらは将来の独立した拡張研究とする。

## 2. 正式なローカル完結条件

コア成果物は、次をすべて満たさなければならない。

1. **一台の汎用PCで動く**  
   Windows、Linux、またはmacOS上の一般的なx86-64 / ARM64コンピューターを対象とする。

2. **CPUだけで参照動作できる**  
   GPUは任意の高速化手段であり、理論検証、デモ、標準テスト、基準ベンチマークの必須条件にしない。

3. **実行時に外部APIを必要としない**  
   OpenAI等のLLM API、クラウド推論、外部データベース、SaaS認証、外部キュー、遠隔ストレージを必須にしない。

4. **研究データがローカルに残る**  
   config、trace、checkpoint、raw result、生成レポートは、利用者が指定したローカルディレクトリへ保存する。

5. **セットアップ後はオフライン実行できる**  
   Pythonパッケージ等の初回取得にはインターネットを利用してよい。ただし依存関係を導入した後の、通常実行・実験・再生・可視化はネットワークなしで成立させる。

6. **UIもローカルで完結する**  
   静的HTMLを直接開く方式、または `localhost` 上のローカルサーバーを認める。外部CDNからJavaScriptやCSSを取得する構成は、正式な配布ビルドでは使用しない。

7. **再現手順をローカルコマンドで提供する**  
   CIが存在しても、それだけを検証手段にしない。CIで行う検査には、対応するローカルコマンドを必ず用意する。

## 3. コア構成で許可されるもの

次はローカル完結の範囲内とする。

- Python 3.11以降
- Python標準ライブラリ
- NumPy、PyTorch、PyTorch Geometric等のローカルライブラリ
- snnTorch、Norse、Nengo、Brian2等によるローカルSNNシミュレーション
- ローカルGPU、Apple Silicon GPU、内蔵NPUの任意利用
- FastAPI等で起動する `127.0.0.1` / `localhost` のUI
- ブラウザ内で動く、配布物に同梱されたJavaScript
- ローカルファイルによるcheckpoint、trace、データセット、レポート管理
- Dockerによるローカル再現環境

これらを利用しても、CPU参照実装は維持する。

## 4. コア完成条件に含めないもの

以下は、SparkBrain本体を完成させるための必須条件にしない。

- Intel Loihi等の専用ニューロモーフィックチップ
- FPGA / ASICへの移植
- クラウドGPUでの大規模学習
- 複数マシンによる分散処理
- 実機の消費電力比較
- リモートLLMを「言語器官」として必須接続すること
- SaaSダッシュボード、クラウドDB、遠隔テレメトリ

これらがなくても、理論・エンジン・シミュレーター・可視化・実験・比較が完成していれば、コアプロジェクトは完成とみなせる。

## 5. 独立拡張トラック

専用ハードウェア研究は、コアロードマップから分離し、次の独立トラックとして扱う。

### Extension H — Dedicated Hardware Validation

目的:

- ローカルシミュレーションで成立したSpark dynamicsを専用基盤へ写像する
- event sparsityが実消費電力やレイテンシへ結びつくか測定する
- rate-based版、ローカルSNN版、専用ハードウェア版の挙動差を記録する

開始条件:

1. ローカル参照エンジンの不変条件が固定されている
2. ローカルSNN版の挙動許容差が定義されている
3. ベンチマークと入力負荷が固定されている
4. 電力・レイテンシ測定方法が事前登録されている

Extension Hの成否は、コア理論の完成判定と分離する。

## 6. ローカル実行の標準レベル

### L0 — 読める

- ソースと文書を展開できる
- 生成済みVisualizerをブラウザで閲覧できる

### L1 — 再生できる

- 既存traceをローカル再生できる
- checkpointを読み込める

### L2 — 実験できる

- demo、world、benchmark、testをCPUで実行できる
- 新しいtraceとreportを生成できる

### L3 — 操作できる

- Brain Labをlocalhostで起動できる
- pause、step、刺激注入、Spark抑制、分岐実験ができる

### L4 — 学習できる

- routingまたは接続をローカル学習できる
- 学習済み状態を保存・再読込できる
- CPU参照用の小規模設定がある

### L5 — ローカル人工脳実験環境として完成

- 複数Worldで連続稼働する
- 内部状態を観測・介入・再生できる
- 比較実験と理論検証を一台のPCで再現できる
- ネットワークを切断しても主要機能が動く

## 7. 受入検査

v0.2.1以降、少なくとも次をローカルで確認する。

```bash
python scripts/local_readiness_check.py
python -m pytest -q
python scripts/run_demo.py
python scripts/checkpoint_demo.py
python scripts/replay_trace.py
python scripts/run_benchmark.py --episodes 40 --steps 30
python scripts/validate_bundle.py
```

`local_readiness_check.py` は、バージョン、必須ファイル、コアの外部ランタイム依存、既知のネットワーククライアント依存を検査する。

## 8. 判断原則

- 高速だがクラウド必須の構成より、遅くてもローカルで説明可能な構成を優先する。
- GPU専用実装を追加する場合、CPUで意味的に等価な参照経路を残す。
- UI技術を選ぶ際は、配布後に外部ネットワークを要求しないことを優先する。
- 外部LLMは比較対象または任意アダプターにはできるが、人工脳コアには含めない。
- 「ローカルで動く」と「小さな計算量で動く」は別の主張として測定する。
