# SparkBrain v0.6 Protocol Amendment 001
## From Missing-Middle-Centred Completion to Functional Endogenous Sparks

**Amendment date:** 2026-08-29  
**Branch:** `v06`  
**Applies before:** any confirmatory v0.6 scientific Gate evaluation  
**Does not rewrite:** v0.5 evidence, the G0 negative diagnostic, or V06-00–V06-06 engineering results

## 1. Reason for the amendment

The first v0.6 plan correctly removed explicit Assembly state from the Primary runtime and created a
path from persistent Field state to endogenous proposals, normal-rule reinjection, and external
correction. However, it placed forward missing-middle completion too close to the centre of the
scientific claim.

A sequence such as:

```text
A -> B -> [C omitted] -> D
```

is a useful validity assay, but a local transition predictor can solve it without establishing the
broader SparkBrain proposition.

The deeper question is whether a persistent Dynamic Field can generate a Spark that is not directly
given by the current external input, allow that Spark to participate causally in later internal
Dynamics and behaviour, and acquire stable externally correctable functional relations through
continued interaction with the world.

## 2. Revised central question

> Can a persistent Dynamic Field generate endogenous Sparks that are not direct copies of current
> external input, let those Sparks causally participate in subsequent internal Dynamics,
> prediction, action, and memory, and form stable revisable functional relations through later
> interaction with the external world, without an explicit Assembly or semantic unit in runtime?

Japanese working form:

> 持続するDynamic Fieldは、現在の外界入力から直接与えられていないSparkを内生的に
> 発生させ、そのSparkを後続の内部Dynamics・予測・行動・記憶へ因果的に参加させ、
> さらに外界との継続的相互作用を通じて安定し訂正可能な機能的関係を形成できるか。

## 3. Meaning is not a stored value

v0.6 must not add fields such as:

```text
meaning = "danger"
semantic_state = "food"
concept_label = "cat"
```

A possible functional meaning is instead treated as a relation pattern:

\[
FunctionalRelation(X) \approx Relations(
    X,
    OtherInternalEvents,
    Predictions,
    Actions,
    MemoryChanges,
    ExternalConsequences,
    Corrections
)
\]

The runtime may learn local transition, action-bias, eligibility, and externally confirmed relation
state. It must not store a human semantic label. A post-hoc observer may describe recurring
functional relation patterns but must not feed them back into the Primary runtime.

## 4. Endogenous Spark levels

### Level 1 — Endogenous Event

A Spark originated internally rather than from a direct external pulse. This is necessary but weak;
noise can satisfy it.

### Level 2 — Predictive Endogenous Spark

An endogenous Spark is generated from persistent state before a later external event and predicts a
future Field or world transition better than matched noise, echo, and frequency controls.

### Level 3 — Functionally Relational Endogenous Spark

An endogenous Spark or lineage:

- changes later internal Dynamics;
- changes a prediction;
- changes an action or action bias;
- changes a memory or eligibility update;
- enters a stable relation with later external consequences;
- remains externally correctable;
- loses the relevant function under targeted intervention beyond matched random controls.

Level 3 is the central v0.6 target. It is not a claim of semantic understanding.

## 5. Missing-middle position after the amendment

Missing-middle is no longer the Primary Goal or a required standalone scientific Gate.

It becomes one **Endogenous Spark Validity Assay**:

```text
Can the system generate a useful internally originated event before a later external cue?
```

The existing strict forward criterion remains mandatory whenever this assay is used:

\[
t(C_{endogenous}) < t(D_{external})
\]

Retrospective reconstruction after D remains a separate secondary metric.

## 6. New primary evidence families

1. **Non-copy origin** — the endogenous event is not a direct echo of the current external pulse.
2. **State dependence** — the same external input under different persistent Field states produces
   different endogenous events.
3. **Autonomous internal continuation** — an endogenous event causes later endogenous Field events
   under external silence and bounded generation.
4. **Causal participation** — removing the event or responsible dynamic pathway selectively changes
   later Dynamics, prediction, action, or memory.
5. **Functional relation acquisition** — repeated externally confirmed relations improve future
   prediction or action without a human semantic label.
6. **External correction** — contradictions reduce, redirect, or retire the relation without
   self-confirmation.
7. **Functional equivalence candidate** — physically different trajectories may be post-hoc grouped
   only when they have stable matched functional relations.
8. **Missing-middle** — retained as one controlled validity assay rather than the project centre.

## 7. Preserved invariants

The amendment does not relax the following:

- Assembly remains observer-only in the Primary runtime.
- Endogenous events are predictions, not observations.
- Positive learning requires later registered external confirmation.
- Internal events cannot confirm themselves.
- Observer ON/OFF runtime state must remain identical.
- Endogenous pulses pass through ordinary Field rules.
- Generation remains bounded by confidence, energy, depth, lifetime, and branch budgets.
- G3 generic recurrent and G4 explicit Assembly-conditioned systems remain comparators.
- G0 remains unsupported after the retained queue-drain diagnostic.

## 8. Effect on existing implementation

V06-00–V06-06 remain valid engineering foundations:

```text

G0 diagnostic

G2 externally confirmed local adaptation
normal-rule reinjection
```

They are reinterpreted as the substrate for Level 1–3 endogenous Spark experiments rather than as a
pipeline whose main purpose is missing-middle completion.

## 10. Scientific integrity

No confirmatory v0.6 Gate result had been evaluated when this amendment was adopted. Existing
engineering code and negative findings are retained. The pre-amendment protocol remains in Git
history, and all future reports must cite this amendment rather than presenting the new direction as
if it had been the original preregistration.
