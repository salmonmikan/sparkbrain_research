# SYSTEM_BUILD workflow

1. Read current Analyst build allocation and exact build branch/head.
2. Confirm build_id, target capability, component/provenance map, interfaces/state loop, acceptance tests, resource budget, limitations and explicit claim boundary.
3. Reuse established/reduced components when they provide the required function; preserve prior scientific results and transfer zero inherited scientific credit.
4. Implement the smallest complete integration slice.
5. Verify current-head CI and acceptance tests.
6. Track separately:
   - built;
   - functionally verified;
   - comparatively supported;
   - composition contribution;
   - scientifically novel;
   - unresolved.
7. Mandatory Codex/code review is not a build gate under the active user-approved policy. Review findings that identify real defects remain normal engineering defects.
8. Build observations remain NON_EVIDENTIARY_BUILD.
9. If an interesting scientific phenomenon appears, return it to Analyst as a development observation. Do not self-promote it; fresh science needs a new prospective object.
10. Use the persistence skill for durable build state.
